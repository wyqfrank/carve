# Ticket 6.2 -- Implement Candidate Serialization for Output

**Epic:** 6 -- Reporting Upgrade
**Complexity:** Low

## Goal

Define stable output serialization for final candidate results.

## Add

- `jpeg_meta`
- `corruption`
- `status`
- `confidence`
- `patched_eoi`
- `start`
- `end`

## Responsibilities

- Ensure candidate structs serialize cleanly
- Keep output deterministic
- Support JSON/JSONL reporting later

## Definition of Done

- [x] Final candidate result serializes successfully
- [x] Output contains all recovery metadata needed by CLI

## Implementation

`report.rs` defines `JsonlRecord` with all required fields, `JpegMeta`, and `CorruptionInfo` sub-objects.
- `JsonlRecord::from_validated(&ValidatedCandidate)` maps all fields including `patched_eoi` → `corruption.eoi_patched`
- `JsonlRecord::to_json_line()` produces deterministic JSON-lines output without external dependencies
- Covered by unit tests: `maps_validated_candidate_into_nested_schema` and `serializes_json_with_jpeg_meta_and_corruption_objects`
