# Ticket 2.11.4 — Integrate Decode Scoring into Reconstruction Pipeline

**Epic:** 2.11 — Decode-Aware JPEG Validation & Scoring
**Complexity:** Medium

## Goal

Replace or augment entropy-based scoring with decode-based scoring in Phase 2.

## Scope

Update:
`reconstruct/scorer.rs`

Pipeline:

`rebuild candidate`
→ `decode`
→ `compute image metrics`
→ `compute score`
→ `rank candidates`

Support:

- fallback to entropy score if decode fails
- optional flag: `--decode-score` (enable/disable)

## Deliverables

- integrated scoring pipeline
- updated candidate ranking logic

## Acceptance Criteria

- [x] Best candidate is visually correct most of the time
- [x] System still works if decoding fails
- [x] CLI remains stable

## Implementation

- `crates/carve-core/src/reconstruct/scorer.rs` — added `RankedScore` and `score_rebuilt_candidate(...)`
- `crates/carve-core/src/reconstruct/rebuilder.rs` — offset search now computes entropy score, optional decode score, and a final ranking score per result
- `crates/carve/src/main.rs` — added `--decode-score` and updated offset-search ranking/output to use final pipeline scores
- `crates/carve-core/tests/benchmark_phase_comparison.rs` — benchmark ranking now follows the pipeline’s final score field
- Decode-aware scoring is opt-in and falls back to entropy scoring automatically if decode fails
