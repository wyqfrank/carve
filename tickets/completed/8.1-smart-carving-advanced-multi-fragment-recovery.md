# Feature Request: Advanced Multi-Fragment (Non-Contiguous) Recovery (Smart Carving)

## Motivation
Currently, Carve implements "linear" or "contiguous" recovery. When given truncated disk fragments, the engine must either accept truncated output, or rely on the user to manually concatenate sequential disk sectors via the CLI before scanning. However, file systems often fragment large files across non-consecutive areas of a disk. When a JPEG is heavily fragmented non-contiguously, linear concatenation fails to piece the image back together, resulting in severe visual corruption or early termination of the entropy scanner.

To truly excel at recovery, Carve must implement **Smart Carving** — mathematically identifying and piecing together non-contiguous fragments of a corrupted image.

## Proposed Strategy (Structural Validation Assembly)

Because the JPEG structure has no embedded FAT table / allocation map, the engine must assemble random unallocated clusters using structural validation.

### 1. Bitstream / Huffman Alignment Scanning
When the entropy scanner hits a boundary (the end of a cluster/fragment), it cannot assume the next byte on disk is the continuation. The engine must scan arbitrary fragments on disk and attempt to resume Huffman decoding across the boundary.
- **Criteria:** If decoding resumes smoothly across the seam without producing invalid markers, mathematical crashing, or MCU (Minimum Coded Unit) desynchronization, the fragment is an extremely high confidence match for continuation.

### 2. Restart Marker (RST) Tracking
Many JPEGs utilize Restart Markers (`FF D0` -> `FF D7`) at regular intervals.
- **Criteria:** If a fragmented JPEG slice ends shortly after encountering `FF D3`, the engine can instantly filter the disk for unallocated clusters that begin with (or quickly contain) `FF D4`. This drastically narrows the search space for the next fragment.

### 3. MCU Boundary Visual Validation
A JPEG is constructed in 8x8 or 16x16 MCUs. Even if bitstream decoding technically succeeds across a mismatched boundary, the visual result will be garbled (e.g., sky pixels suddenly attaching to sand pixels).
- **Criteria:** By evaluating the decoded edge differentials (checking for drastic gradient or color shifts between the last MCU row of Fragment A and the first MCU row of Fragment B), the engine can reject "false positive" mathematical fits and prioritize visually continuous fragments.

## Implementation Plan

**Phase A: Entropy Decoder Integration**
The current `scan_entropy_stream` function inside `entropy.rs` operates at the byte level strictly searching for markers and `0xFF` stuffing. It does not actively decompress the Huffman stream.
- Integrate or build a lightweight, bounds-safe Huffman decoder.
- Track DC/AC coefficient state precisely at the point of cluster interruption.

**Phase B: Fragment Combinatorics & Search**
- Introduce a mechanism to chunk large disk images into standard cluster sizes (e.g. 4KB / 8KB / 32KB depending on the filesystem parameters).
- When a truncated JPEG is found in Cluster A, begin querying a pool of unallocated clusters.
- Apply fast filters first (RST markers, magic bytes) before attempting expensive Huffman re-synchronization tests.

**Phase C: Scoring and Assembly**
- Expand `validate.rs` and the `confidence_score` model to grade the quality of cluster "seams".
- Output the fully assembled multi-fragment memory buffer to the `extract_candidates` pipeline.

## Acceptance Criteria
- [ ] Add a lightweight Huffman decoding/tracking state to the entropy scanner.
- [ ] Ability to input a raw disk image, define a cluster size, and have the engine search beyond contiguous bounds for truncated images.
- [ ] Add unit tests that inject garbage data between two halves of a valid JPEG, ensuring the engine correctly drops the garbage and attaches the two halves structurally.
