# Ticket 2.11.1 — Integrate JPEG Decoder

**Epic:** 2.11 — Decode-Aware JPEG Validation & Scoring
**Complexity:** Low

## Goal

Add the ability to decode reconstructed JPEG candidates into pixel data.

## Why

Current scoring operates on compressed entropy bytes and cannot detect:

- colour corruption
- block misalignment
- visual artifacts

Decoding is required to evaluate actual image quality.

## Scope

Add dependency:
`jpeg-decoder = "0.3"`

Implement a decoding utility:
```rust
fn decode_jpeg(bytes: &[u8]) -> DecodeResult
```

Where `DecodeResult` contains:

```rust
pub struct DecodeResult {
    pub success: bool,
    pub width: Option<u16>,
    pub height: Option<u16>,
    pub pixels: Option<Vec<u8>>, // RGB
}
```

## Deliverables

- JPEG decoding module (e.g. `decode.rs`)
- Graceful handling of decode failures (no panics)

## Acceptance Criteria

- [x] Can decode valid rebuilt JPEGs
- [x] Returns failure for corrupted images without crashing
- [x] Width/height and pixel buffer are accessible

## Implementation

- `crates/carve-core/src/reconstruct/decode.rs` — `DecodeResult`, `decode_jpeg`
- `crates/carve-core/src/reconstruct/mod.rs` — exports decode module
- `crates/carve-core/Cargo.toml` — adds `jpeg-decoder = "0.3"`
- Decoding returns RGB pixel buffers and gracefully returns an empty failure result on decode errors
- Tests cover a real JPEG fixture decode path and corrupted-byte failure handling
