# Ticket 2.6 — Implement Entropy Offset Search

**Epic:** 2 — Camera-Aware JPEG Reconstruction
**Complexity:** High

## Goal

Improve recovery quality by testing small byte offsets into the carved entropy stream before rebuilding the JPEG.

## Why

Block duplication and horizontal shift artefacts strongly suggest that some candidates start decoding mid-MCU. Testing multiple offsets finds the alignment that produces the least corruption.

## Scope

Implement a search routine that, for each carved entropy stream, tries a bounded range of start offsets such as `0..=512 bytes`. For each offset:

- rebuild JPEG with Canon header
- save candidate
- optionally score candidate quality

At minimum, the system should support generating multiple candidates per carved image.

## Deliverables

- Offset search routine
- Configurable offset search range
- Multiple candidate outputs per source carve

## Acceptance Criteria

- [x] System can generate reconstruction attempts for several offsets
- [x] Output file naming identifies the offset used
- [x] Some previously block-shifted images show visible improvement

## Implementation

- `rebuild_with_offset_search` in `crates/carve-core/src/reconstruct/rebuilder.rs`
- `OffsetSearchOptions { max_offset, step }` with `Default` (512, 1)
- Output naming: `rebuilt_NNN_offset_MMMM.jpg`
- CLI: `--offset-search` and `--offset-max N` flags; `--offset-max` implies `--offset-search`
