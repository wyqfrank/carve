# Ticket 6.4 -- Implement Recovered JPEG Extraction

**Epic:** 6 -- Reporting Upgrade
**Complexity:** Medium

## Goal

Write recovered candidate byte ranges out as `.jpg` files.

## Responsibilities

- Slice original byte stream using candidate start/end
- Apply optional EOI append if patching enabled
- Name outputs deterministically
- Preserve emitted ordering

## Definition of Done

- [x] Recovered JPEG files written to output directory
- [x] Truncated patched files include EOI when enabled
- [x] File naming deterministic

## Implementation

`extract.rs` implements:
- `ExtractError(io::Error)` — wraps IO errors
- `extract_candidates(bytes, candidates, output_dir) -> Result<Vec<PathBuf>, ExtractError>`
  - Writes `recovered_000.jpg`, `recovered_001.jpg`, … in candidate order
  - Slices `bytes[start..end]` per candidate
  - Appends `FF D9` when `candidate.patched_eoi` is true
  - Returns paths of written files in order
- 5 unit tests covering: slice correctness, EOI append, no spurious EOI, deterministic naming, empty input
