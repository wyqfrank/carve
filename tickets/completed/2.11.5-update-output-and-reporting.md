# Ticket 2.11.5 — Update Output & Reporting

**Epic:** 2.11 — Decode-Aware JPEG Validation & Scoring
**Complexity:** Low

## Goal

Expose decode-based scoring results to users.

## Scope

Update:

filenames (optional):
`rebuilt_000_score_0.92.jpg`

or `report.jsonl`:
Add fields:

```json
{
  "decode_success": true,
  "colour_score": 0.85,
  "entropy_score": 0.91,
  "artifact_score": 0.12,
  "final_score": 0.89
}
```

## Deliverables

- updated reporting format
- clear separation of entropy vs decode score

## Acceptance Criteria

- [x] Users can inspect why a candidate was chosen
- [x] Scores are interpretable and consistent

## Implementation

- `crates/carve-core/src/report.rs` — added optional per-candidate scoring output with entropy/decode separation
- `crates/carve/src/main.rs` — report generation now attaches the best offset-search result for each candidate
- `report.jsonl` now includes a `scoring` object with selected offset, entropy score, optional decode score/components, decode usage, and final score
- Reporting remains stable when offset search is not used: the `scoring` field is emitted as `null`
