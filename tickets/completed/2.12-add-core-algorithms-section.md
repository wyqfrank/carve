# Ticket 2.12 — Add "Core Algorithms & Techniques" Section to README

**Epic:** 2 — Camera-Aware JPEG Reconstruction
**Complexity:** Low

## Goal

Enhance the `README.md` by adding a concise, high-signal section describing the key algorithms and techniques used in the project.

This section should highlight the core technical ideas behind the system, without going into low-level implementation detail.

## Why

The current README already explains:
- what the system does
- the recovery pipeline
- the Canon IXUS 310 HS reconstruction approach

However, it does not explicitly surface the core algorithms that make the project technically interesting.

Adding this section will:
- make the project more compelling to recruiters and engineers
- clearly communicate technical depth
- differentiate it from basic file carving tools

## Scope

Add a new section:
```markdown
## Core Algorithms & Techniques
```

Place it after:
```markdown
## Why JPEG Recovery Is Hard
```
and before:
```markdown
## Recovery Pipeline
```

## Content Requirements

Include 4–5 key techniques only, each explained in 2–4 concise sentences.

Avoid implementation detail. Focus on:
- what the technique does
- why it matters

### Required Topics

**1. Entropy-Aware JPEG Scanning**
Explain:
- handling of `FF00` byte stuffing
- safe traversal of entropy stream
- avoidance of false marker detection

**2. Candidate Scoring & Ranking**
Explain:
- entropy-based scoring (Shannon entropy, byte diversity)
- invalid marker penalties
- why scoring is needed to prioritise candidates

**3. Camera-Specific Header Reconstruction (Canon IXUS 310 HS)**
Explain:
- use of invariant DQT and DHT tables
- rebuilding valid JPEG headers
- why this fixes colour and decoding issues

**4. Entropy Offset Search**
Explain:
- misalignment when carving mid-MCU
- bounded offset search (e.g. 0–512 bytes)
- improvement of block/shift artifacts

**5. (Optional / Future-facing)**
If already implemented or planned:
- decode-based scoring
- fragment recovery

Keep this short and clearly marked as future work if not yet implemented.

## Non-Goals

Do **NOT** include:
- full JPEG specification explanations
- Huffman decoding internals
- bit-level compression details
- large code snippets

Deep technical content should go into `/docs`, not the README.

## Deliverables

- Updated `README.md`
- New "Core Algorithms & Techniques" section
- Clear, concise explanations (2–4 sentences per item)

## Acceptance Criteria

- Section is easy to read in under 1–2 minutes
- Contains only the most important techniques (no clutter)
- Improves perceived technical depth of the project
- Does not duplicate content already explained elsewhere in the README
